先看这里

不要从 src 开始，从 README.md 开始

先建立系统全貌，再进入代码。第一个 Java 业务文件看首页控制器， 第一段核心业务链看查询功能。不要一开始就打开后台控制器或权限过滤器。

第一入口 README.md

了解功能、演示账号、启动方式、四张表和技术栈。

第一个 Java 业务文件 src/main/java/com/keshe/crop/controller/HomeController.java

用最短的一条链理解 Controller、Model 和 Thymeleaf。

第一段核心业务链 SearchController → CropService → CropRepository.search → search.html

查询是这个项目的心脏。看懂它，项目就理解了一大半。

不要从 AdminController.java 或 AuthFilter.java 开始。它们分支多、细节多，适合在掌握主线之后再读。
01

Mental Model

先建立整体地图

这个项目是典型的 Spring MVC 分层 + Thymeleaf 服务端渲染。

目录 作用 学习重点
controller 接收浏览器请求 URL 如何对应到 Java 方法
service 业务规则 查重、事务、收藏切换
repository 数据访问 JdbcTemplate 和原生 SQL
model JavaBean、表单、分页 数据如何从数据库传到页面
filter 登录和权限 Session、Filter、角色判断
templates Thymeleaf 页面 th:* 如何渲染数据
static CSS、JS、图片 表单验证和页面交互
db 建表脚本和演示数据 四张表的关系
浏览器→ AuthFilter→ Controller→ Service→ Repository→ MySQL→ Model→ Thymeleaf→ HTML

后面每读一个功能，都沿着这条线找。不要东看一个文件、西看一个文件。 先在 Controller 找到 URL，再往下追 Service、Repository，最后回到模板。

01

数据地基 · 四张表

数据库先行

约 1 天

目标：看懂数据怎么存，理解表之间的关系，再去看 Java 代码。

阅读顺序

这一阶段要搞懂

  • crop 一对多 oil_record
  • app_user 和 crop 通过 favorite 多对多
  • 为什么含油率记录要单独建表

动手练习

执行下面的 SQL，再统计每种植物有几条含油率记录。

SELECT c.chinese_name, c.family,
       o.origin, o.oil_content
FROM crop c
JOIN oil_record o ON o.crop_id = c.id
ORDER BY o.oil_content DESC
LIMIT 10;
验收：能解释四张表的关系

10

Reading Method

读代码时固定问五个问题

每看一个功能，都按这个模板记笔记，比从头读到尾有效得多。

Q1

浏览器请求的是哪个 URL？

Q2

哪个 Controller 方法接收？

Q3

调用了哪个 Service 或 Repository？

Q4

执行了什么 SQL，操作哪张表？

Q5

数据怎样进入 Thymeleaf 模板？

示例：查询功能
URL：GET /search?keyword=松&family=松科
Controller：SearchController.search()
Service：CropService.search()
Repository：CropRepository.search()
SQL：动态 WHERE + LIMIT/OFFSET
Model：result、selectedFields、families、genera
模板：search.html

调试技巧

  • 断点：在 Controller 方法里打断点，再单步进入 Service 和 Repository。
  • 浏览器：F12 的 Network 面板看请求参数、响应状态和 Cookie。
  • SQL：临时把 logging.level.org.springframework.jdbc.core 设为 DEBUG，观察实际执行的 SQL。
  • 模板：右键查看网页源代码，注意 Thymeleaf 标签已经被渲染成普通 HTML。
11

Avoid Traps

初期不要做的事

不是这些内容不重要，而是现在读性价比太低。

  • 不要一开始读 AdminController.java，它 294 行，分支最多。
  • 不要从头到尾读 data.sql，那是数据，不是逻辑。
  • 不要逐行读所有 getter/setter，知道字段含义即可。
  • 不要读 static/vendor/bootstrap/**，那是第三方库源码。
  • 不要一开始研究 CSS 的每个类名，先看懂页面结构。
  • 不要同时打开十几个文件，按“一个功能一条链”读。
12

Three-Day Version

如果只有三天

先能讲清楚“查询功能”和“登录权限”，再补后台和前端细节。

DAY 1

README.md → schema.sql → HomeController + index.html → 查询链 SearchController / CropService / CropRepository.search / search.html。

DAY 2

详情页与收藏 → AuthController + AuthService + UserRepository → AuthFilter。重点能画登录流程和权限判断。

DAY 3

AdminController 的作物 CRUD → CropForm → CropRepository 的增删改 → crop-form.html。最后跑一次 mvn test。

13

Final Check

最终检验：完整加一个字段

这是判断你是否真正理解这个项目的最好练习。

给植物增加一个“植株高度”字段，要求能在后台新增、编辑，在详情页展示，并且做服务端校验。 按下面的顺序改，改完再运行测试：

db/schema.sql→ model/Crop.java→ model/CropForm.java→ repository/CropRepository.java→ admin/crop-form.html→ crop/detail.html→ 表单校验

如果卡住了，回到这条线

数据库字段 → JavaBean 字段 → 表单字段 → RowMapper 映射 → INSERT/UPDATE 参数 → 模板显示。 任何一层漏掉，页面都不会出现你想要的数据。能独立排查，就说明你已经具备修改这个项目的能力。
